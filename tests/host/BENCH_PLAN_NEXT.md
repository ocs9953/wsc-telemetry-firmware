## 0. 세션 시작 (매번)

**전원 넣기 전에: BAT 코인 배터리(H1)가 꽂혀 있는지 본다.** 이 보드는 VBAT 가
코인 홀더에만 연결돼 있고 3.3V 와 이어져 있지 않다(넷리스트 확인). 빠져 있으면
VBAT 핀이 떠서 데이터시트 조건 밖이고, 전원을 껐다 켤 때마다 RTC 가 빌드 시각으로
되돌아간다. 2026-09-21 시험이 코인 배터리 없이 진행됐다 — 영향 검토 결과는
`SD_FAULT_VALIDATION_2026-09-21.md` 의 "코인 배터리" 절을 볼 것.

```
.\tests\host\bench_session.ps1 -Flash
```

빌드 → 플래시 → 사전 점검까지 하고 **GO / NO-GO** 를 출력한다. 점검 항목:

- 보드에 실제로 올라간 이미지가 방금 빌드한 ELF 와 같은가 (플래시 readback SHA256)
- 보드가 돌고 있고 직전 리셋 원인이 무엇인가
- SD 가 마운트돼 있고 복구 중이 아닌가
- 이전 주입이 남긴 마스크가 없는가 (SDMMC 클럭 / SDMMC IRQ / FDCAN1 IRQ)
- CAN A·B 에 실제로 프레임이 흐르는가 (1초 간격 두 번 읽어 증가 확인)
- 세마포어 7 / 스레드 8 인가

### 이 스크립트의 검증 상태 (정직하게)

보드를 붙인 경로는 아직 못 돌려봤다 — 위 "준비 상태" 표 참고. 가짜 OpenOCD 로
판정 논리는 확인했으니, **처음 붙이는 날 이 스크립트부터 돌려서** 실제 응답 형식이
같은지만 보면 된다. 안 되면 거기부터 고친다.

`-NoCan`: CAN 이 필요 없는 작업(1 번 리셋 관측, SD 만 보는 시험)에서는 Bus A 가
조용해도 NO-GO 로 막지 않는다.

덧붙임: 이 설치본의 `interface/stlink.cfg` 는 swj-dp.tcl 에서 무한 재귀로 죽는다.
그래서 `stlink-dap.cfg` 를 쓴다.

NO-GO 면 그대로 멈추고 원인부터 본다. 플래시 없이 상태만 보려면 `-Flash` 를 뺀다.
CubeProgrammer 를 써야 하면 `-StopOpenOcd` 로 프로브를 넘긴다 (OpenOCD 가 프로브를
독점해서, 안 넘기면 `DEV_CONNECT_ERR` 이 뜬다 — 보드가 죽은 게 아니다).

## 4. Bus B 연속성 (더미 한 대 이동)

**왜 필요한가**: Bus B 에는 순번 계측이 없어서, 지금까지 Bus B 연속성은 프레임
간격과 TEC/REC 로만 판정했다. 넘침 카운터(`g_mcp_rx_ovf`)는 한 번도 증가한 적이
없어 검증되지 않았다.

사람이 할 일: 모터 더미를 **Bus B 배선으로 옮긴다**.

모터 더미는 이미 `DUMMY_HEARTBEAT_ID = ID_TEST_HEARTBEAT_BUS_B` (0x51F) 로 맞춰
뒀다. 굽기만 하면 된다:

```
cd tests\dummy_nodes
bash build_dummy.sh Motor flash
```

0x51F 를 고른 근거: MCP 수신 필터가 0x510~0x51F 만 통과시키는데 필터를 넓히면
제품 동작이 바뀐다. 그 창 안에서 브리지 화이트리스트에 없는 값이라 조용히 무시된다.

## 5-1. LV BMS 복원 확인 (2026-09-23 복원, 실기 미검증)

**왜**: 펌웨어·지상국·더미를 다 고쳤지만 **보드에서는 한 번도 안 돌려봤다.**
확인한 것은 빌드 3구성, 실제 CMU 파서를 돌리는 호스트 시험, 지상국 단위 시험까지다.

BMS 더미를 새로 구우면 HV(구 BQ 형식)와 함께 **LV(0x600, Prohelion 형식)** 를 보낸다:
```
cd tests\dummy_nodes
bash build_dummy.sh BMS flash
```

보는 것:
- `VehicleData.bms_lv` 가 채워지는가 — 팩 12~14V, 셀 4개 3.0~3.5V, 셀 4~7 은 -32768
- `VehicleData.bms` (HV) 가 LV 값으로 **오염되지 않는가** — 두 BMS 가 같은 오프셋 표를 쓰므로 가장 먼저 확인
- 무선에 SRC 8 의 PACK_VI / SOC_TEMP 가 1초마다 나오는가 (`analyze_fault_radio.js`)
- 지상국 메인 화면 "보조 SOC / 보조 전압" 칸, 신선도 26·27
- LV 더미를 끄면 "LV BMS 무응답" 경고가 한 번 뜨는가 (`g_timeout_mask` 비트 11·12)
- **LV 는 새로 만든 하드웨어 필터 2(0x600~0x6FF)로 들어온다** (2026-09-28). 위 첫 항목이
  맞으면 필터 2 가 동작하는 것이다. `g_init_fail_mask` 비트 0 이 서 있으면 FDCAN 초기화가
  필터 수 부족으로 실패한 것 — `fdcan.c` 의 `StdFiltersNbr` 가 3 인지 본다.
- 0x5xx 는 이제 하드웨어에서 걸러진다. 필터를 둘로 넓혀 받던 이전 방식에서 생기던
  "실제 Bus A 에 0x5xx 트래픽이 있나" 라는 질문 자체가 없어졌다.

⚠ BMS 더미의 **HV 쪽은 아직 구 BQ 형식**이라 HV 값은 실물과 다르게 읽힌다. 그건
이번 확인 대상이 아니다.

## 6. 장애 주입 재확인 (계측 전부 켠 상태로)

1~5 가 정리된 뒤, 계측이 다 붙은 상태에서 한 번 더 돌린다.

관측을 **먼저** 띄우고(별도 창), 그다음 주입을 건다. 관측은 주입보다 길게 잡는다.
```
node tests\host\observe_bench.js --seconds=90 --build=build/bench --output=build\final_irq_obs
node tests\host\sd_irq_fault.js --inject-sd-irq --hold-ms=10000 --repeat-mask --build=build/bench --output=build\final_irq

node tests\host\observe_bench.js --seconds=90 --build=build/bench --output=build\final_idle_obs
node tests\host\sd_idle_stall.js --inject-idle-stall --stall-ms=12000 --repeat-mask --build=build/bench --output=build\final_idle
```
두 도구를 동시에 띄우면 OpenOCD 가 먼저 붙은 쪽에 접속 알림을 보낸다. 2026-09-28 에
세 도구 모두 그 알림을 응답으로 착각하지 않게 고쳤고 가짜 OpenOCD 로 확인했다.
관측 결과는 `node tests\host\summarize_bench.js build\final_irq_obs` 로 요약한다.
출력 폴더는 매번 새 이름으로 — 관측·캡처 도구는 기존 증거를 덮어쓰지 않고 멈춘다.

`--repeat-mask` 없이 돌리면 장애가 1~2초 만에 저절로 끝난다 — 복구 경로가
주변장치를 다시 잡으면서 클럭과 IRQ 를 스스로 되살리기 때문이다. 스크립트가
**실제 무응답 시간**(`measuredOutageMs`)을 따로 기록하니 그 값으로 판정한다.

## 추후 반영 (예약된 작업)

### VBAT 코인 배터리 전압 측정 — 2026-09-28 결정, 2026-09-29 구현·**실기 확인 완료**

구현: `KEY_SYS_VBAT` = 17, 부팅 직후 + 60초마다 무선+SD (`can-signal-summary.md` §4.8).
지상국 대시보드에 값과 상태(정상 / 교체 필요 / 없음)가 표시된다.
실측 (2026-09-29): 코인 있음 보드 3,292 mV / 멀티미터 3,252 mV, 코인 없음 1,027 → 960 mV.
측정 5회 실패 0, 측정 사이 VBAT 경로 꺼짐(CCR VBATEN=0) 확인. 문턱 2.0 V / 2.7 V 확정.
남은 확인 하나: ADC 포텐셔미터 값이 전과 같은지 (injected 변환을 끼워 넣었으므로 — J3 센서를 달 때).

아래는 결정 당시의 메모다.

**왜**: 2026-09-21 시험이 코인 배터리 없이 진행됐는데 아무것도 그걸 알려주지 않았다.
이 보드는 VBAT 가 코인 홀더(H1)·C24 에만 연결돼 있어 ADC 가 **코인 셀 자체**를 잰다.
그러니 보드가 부팅 때 "코인 배터리 없음" 을 스스로 보고할 수 있다.

**할 수 있는 것과 없는 것**:
- 전압은 읽는다 — ADC1 내부 채널 `ADC_CHANNEL_VBAT` (칩 안에서 1/4 분압, `LL_ADC_PATH_INTERNAL_VBAT`)
- 용량(%)은 못 읽는다 — 리튬 코인 셀은 수명 대부분 약 3.0 V 로 평평하다가 끝에서 떨어진다.
  판정은 **정상 / 교체 시기 / 없음** 세 단계가 한계다

**구현 메모**:
- `adc_sensor.c` 는 이미 VREFINT 로 실제 VDDA 를 보정한다 — 같은 시퀀스에 VBAT 를 덧붙이거나,
  부팅 1회 + 주기(예: 60초) 단발 변환으로 따로 잰다
- **분압 회로는 변환하는 동안만 켠다** — 켜 둔 동안 코인 셀에서 전류를 끌어간다
- 보고: 부팅 보고(0x95)처럼 무선 1회 + SD 세션 머리. 지상국 `LogErrorKey` 에 이름 추가
- 판정 문턱은 실측으로 정한다: 코인 장착 / 미장착 상태에서 각각 읽어 보고 결정
  (미장착이면 핀이 떠서 값이 불안정할 것으로 예상 — 그 자체를 "없음" 근거로 쓴다)
- 대안: PWR 백업 도메인 감시(`PWR_BDCR1_MONEN`)는 문턱 플래그만 준다. ADC 쪽이 더 낫다
