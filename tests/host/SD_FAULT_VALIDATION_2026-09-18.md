# SD 장애 검증 — 2026-09-18

## 환경 및 방법

- 사용자 확인: 실차가 아닌 더미 보드 구성, SD·무선 연결.
- 현재 펌웨어를 그대로 사용. 재빌드·플래시·보드 halt/reset·CAN 명령 송신 없음.
- ELF: `build/release/WSC_Transmitter_Code_V1.elf`
- ELF SHA-256: `f6a65de05087c096a1d83165175567f4e4b19baf5a2cebc10ce1f85e9984718e`
- 해당 빌드의 map에서 관측 변수 주소를 읽음.
- SDMMC1 IRQ78만 NVIC에서 차단하여 DMA 완료 통지가 누락되도록 주입.
  실제 SD DMA 완료 대기/타임아웃 함수를 실행하며, 복구 카운터를 직접 조작하지 않음.
- COM9/115200을 수신 전용으로 열어 무선 원본 바이트를 기록. RTS/DTR은 기존
  지상국과 동일하게 설정. 원본 COBS/CRC를 재검사하고 패킷별 차량 시각을 비교.
- 지상국은 사용자 승인으로 잠시 종료한 뒤 원래 실행 인자로 재시작.

시간은 약 100ms 간격의 순차 폴링으로 얻은 관측치다. IRQ 차단과 실제 SD 전송
시작은 일치하지 않으므로 1,090ms를 설정된 750ms 타임아웃 자체의 정밀 측정값으로
해석하면 안 된다. 각 행의 변수도 완전히 동시인 스냅샷은 아니다.

### 무선 연속성

- 전체 캡처: 정상 LOG 1,462패킷, COBS 오류 0, CRC 오류 0.
- 장애 주입 3초 전부터 15초 후까지: 378패킷, 차량 시각 역전 0.
- 이 구간의 전체 패킷 최대 도착 간격 495ms, 차량 시각 최대 간격 500ms.
- BMS/MPPT/모터 PRIMARY 및 상태표의 차량 시각 간격 1,000ms 유지.
- 수신한 상세/ADC 항목의 차량 시각 간격 5,000ms 유지.
- GPS 항목의 최대 차량 시각 간격 1,009ms.
- 장애 중 SD 쓰기 오류 패킷도 무선으로 수신 (`src=14`, `key=0x8A`).
- 처음 포트를 열 때 모뎀에 쌓인 백로그가 포함되므로 전체 캡처의 시각 범위를
  실제 녹화 길이로 해석하지 않음. 장애 주변 구간은 별도로 비교했음.
- 이는 이번 관측 구간의 연속성 확인이며, 순번이 없는 모든 패킷의 절대 무손실을
  보장하거나 CAN B까지 확인했다는 뜻은 아님.

## 첫 시도와 관측기 수정

`build/fault_validation_irq1`의 첫 시도에서는 OpenOCD 쓰기 응답에 포함된 NUL을
관측기가 처리하지 못해 타임아웃으로 종료됐다. 별도 연결로 IRQ를 복원하고
활성 상태 및 SD 복구를 확인했다. 이 과정에서 실제 SD 타임아웃은 0→2,
복구 카운터는 3→4로 증가했다. 이 시도는 정밀 타이밍 결과에 사용하지 않는다.
관측기의 NUL 처리를 수정한 후 위 두 번째 시험을 별도로 수행했다.

## 모의 검증 및 남은 범위

`test_sd_timeout.ps1`는 제품의 `fx_sd_io_timeout()` 본문을 추출해 실행한다.
실기와 별개로 아래 5개 레지스터 모의 시나리오에서 모두 통과했다.

1. 상태 머신이 이미 정지한 경우.
2. DPSMACT가 계속 남는 경우.
3. CPSMACT가 계속 남는 경우.
4. 두 활성 비트가 모두 계속 남는 경우.
5. 핸들이 이미 RESET인 경우.

IDMA/CMDTRANS/DTEN 해제, 인터럽트 차단, 잔여 세마포어 배수, 복구 요청,
타임아웃 계수, 강제 리셋 분기 및 RESET 상태 유지 여부를 검사했다.
**이 결과는 실제 실리콘의 상태 머신 고착이나 RCC 강제 리셋 성공을 입증하지 않는다.**

남은 실기 범위: 실제 전송 중 DMA/상태 머신 고착 → 강제 리셋, CAN B 연속성,
이번 타임아웃 시험 후 카드 파일의 오프라인 CRC/FAT 검사 및 반복 내구 시험.
현재 완료 인터럽트 누락 시험에서는 DMA 자체가 먼저 끝날 수 있으므로,
`IDMACTRL=0` 종료 상태만으로 전송 중인 DMA의 즉각 정지까지 증명하지 않는다.
