# Motor_Dummy — Motor(VCU) 대역 노드

Tritium **WaveSculptor22** 모터 컨트롤러가 VCU 를 거쳐 보내는 CAN 프레임을 생성한다.
공통 배선·클럭·코드 삽입 방법은 상위 [`../README.md`](../README.md) 참조.

---

## 1. 송신 프레임 (13종)

**0x401 만 정수이고 나머지 12종은 전부 리틀엔디안 float 다.**

| ID | @0–3 | @4–7 | 주기 |
|---|---|---|---|
| 0x401 FLAGS | Limit u16@0 · Error u16@2 | ActiveMotor u16@4 · TxErr u8@6 · RxErr u8@7 | 1 s |
| 0x402 BUS | Bus_V [V] | Bus_I [A] | 100 ms |
| 0x403 VEL | Motor_rpm | **Veh_Vel [m/s]** | 100 ms |
| 0x404 PHASE_I | PhaseB_I [A] | PhaseC_I [A] | 200 ms |
| 0x405 V_VECTOR | **Vq** [V] | **Vd** [V] | 200 ms |
| 0x406 I_VECTOR | **Iq** [A] | **Id** [A] | 200 ms |
| 0x407 BEMF | **BEMFq** [V] | **BEMFd** (항상 0) | 200 ms |
| 0x408 RAIL_A | *(예약)* | 15V [V] | 1 s |
| 0x409 RAIL_B | 1.9V [V] | 3.3V [V] | 1 s |
| 0x40B TEMP | Motor_Temp [℃] | HeatSink_Temp [℃] | 200 ms |
| 0x40C DSP_TEMP | DSP_Board_Temp [℃] | *(예약)* | 200 ms |
| 0x40E ODO | Odometer [m] | DC_Bus_AmpHours [Ah] | 1 s |
| 0x417 SLIP | *(예약)* | SlipSpeed [rpm] | 1 s |

### [중요] 바이트 순서 함정

0x405 / 0x406 / 0x407 은 매뉴얼 표기가 **"d 63..32 / q 31..0"** 이라
**q 가 byte0–3, d 가 byte4–7** 이다. 직관과 반대다.

0x408 / 0x417 은 **byte0–3 이 Reserved** 이고 유효 데이터가 byte4–7 에만 있다.

이건 이론적 주의사항이 아니다. 2026-07 에 공식 매뉴얼을 입수해 대조한 결과
수신측이 이 5개를 반대로 읽고 있었고, 커밋 `65ee2d9` 로 수정했다.
더미도 반드시 같은 순서로 채워야 대조가 성립한다.

### [중요] Veh_Vel 의 단위는 m/s 다

수신측이 `f_to_u16(v × 100)` 으로 담는다. km/h 로 보내면 지상국 속도가
**3.6배**로 뜨는데, 값이 그럴듯해서 한동안 눈치채지 못할 수 있다.

## 2. 다른 두 더미와 다른 점 — 물리 모델

BMS·MPPT 더미는 신호마다 독립 삼각파를 쓴다. Motor 더미는 **속도 하나만**
삼각파(0–25 m/s, 60초 주기)로 두고 나머지를 전부 그로부터 유도한다.

독립 난수를 쓰면 "속도는 오르는데 전류가 줄어드는" 물리적으로 불가능한 조합이
나와서, 지상국 그래프가 맞게 그려진 건지 틀리게 그려진 건지 **눈으로 판별할 수
없다.** 유도 방식에서는 다음이 자동으로 성립한다.

- **가속 구간에서 Bus_I 가 (+), 감속 구간에서 (−)** — 회생제동
- **BEMF 가 rpm 에 정비례**
- **온도가 부하를 1차 지연으로 따라감**
- **주행거리가 단조 증가**

이 관계가 지상국에서 깨져 보이면 파싱·스케일·부호 처리 중 하나가 틀린 것이다.

### 모델 파라미터

| 항목 | 값 |
|---|---|
| 타이어 원주 | 1.759 m (외경 0.56 m) |
| 차량 질량 | 250 kg (드라이버 포함) |
| 구름저항 | 12 N |
| 공기저항 계수 | 0.200 (F = k·v²) |
| 구동계 효율 | 92 % |
| 최고 속도 | 25 m/s (90 km/h) |

25 m/s 정속 시 주행저항 137 N → 기계 출력 3.4 kW. 실차 솔라카와 같은 규모다.
모터 회전수는 최대 약 853 rpm, BEMF 는 최대 약 98 V 가 된다.

효율은 방향에 따라 반대로 적용한다 — 구동 시엔 손실만큼 더 뽑아쓰고,
회생 시엔 손실만큼 덜 돌려받는다.

## 3. sticky OR 검증

0x401 의 Limit flags 는 **속도가 최대의 90 % 를 넘는 구간에서만** bit0(전류 제한)을
세운다.

수신측은 limit/error flags 를 sticky OR 로 누적하고 스케줄러가 전송 직후
클리어한다. 지상국에서 **속도 그래프의 피크와 제한 비트가 같이 뜨는지**
확인하면 이 경로가 살아 있는지 알 수 있다.

Error flags 는 0 으로 고정했다(정상 주행 시나리오). 오류 경로를 시험하려면
`send_slow()` 의 `error` 를 조건부로 세우면 된다.

---

## 4. 0x40E 는 반드시 보내야 한다

수신측에서 이 프레임만 **별도 신선도 타이머**(`odo_last_tick`)로 감시된다.
2026-08 에 10초 규정 패킷이 제거되면서 **주행거리의 유일한 경로**가 됐다.
